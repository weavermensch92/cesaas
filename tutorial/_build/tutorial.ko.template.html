STEP 1 · 부스 태블릿

딜러 인터뷰 — 31문항 태블릿 설문

CTT 모스크바 부스에서 딜러가 직접 운영하는 태블릿 화면. 인터넷이 끊겨도 작성이 가능하며, 복구되면 응답이 자동으로 본사로 보내집니다. 아래 스크린샷은 진입 직후 첫 단계(1/4 — 고객 정보 입력)입니다.

화면 구성

상단 헤더제품명 · 송출 상태(Online/Offline) · 대기 중인 응답 수 · 과거 인터뷰 이력 · 도움말 · 언어 토글(러시아어 / 영어 / 한국어).
진행 표시4단계 진행도 (1/4 → 2/4 → 3/4 → 4/4).
1단계 — 고객 정보회사명(필수) · 담당자 · 전화 · 미팅 노트. 회사명이 비어 있으면 "다음" 버튼이 비활성.
2~3단계 — 본 설문6개 핵심 축(회사 규모 · 주 용도 · 연간 가동시간 · 디젤 가격 민감도 · 환경 규제 영향 · 의사결정 역할) + 7개 마케팅 보조 문항.
4단계 — 마무리NPS 0–10 · 개인정보 처리 동의 · 송출. 동의 체크가 없으면 응답이 송출되지 않음.

인증과 송출

딜러는 출장 전 발급받은 개인 토큰을 첫 진입 시 한 번 입력하면, 그 뒤로는 추가 로그인이 필요 없습니다. 오프라인 상태에서 작성한 응답은 태블릿에 잠시 보관되었다가 인터넷이 복구되면 자동 송출됩니다. 헤더의 "대기 N" 배지가 송출 대기 중인 응답 수를 보여줍니다.

왜 별도 앱이 아닌가. 부스 환경의 네트워크 변동성을 고려해서, 페이지 자체에 모든 자원을 담아두는 단일 페이지 형태로 만들었습니다. 한 번 로드되면 그 다음부터는 인터넷 없이도 인터뷰 진행이 가능합니다.
STEP 2 · 방문객 모바일

방문객 설문 — QR 스캔 후 2분

방문객이 부스 QR을 스캔하면 자신의 휴대전화에 18문항(필수 12 + 선택 6) 설문이 열립니다. 2분 안에 응답을 마치면 추천 장비 카드 + PDF 카탈로그 QR을 받습니다. 익명 응답이라 별도 로그인이 없습니다. 아래 스크린샷은 1단계(회사 정보) 화면.

4 단계 흐름

1/4 — 회사 정보회사 규모(~50 / 51-200 / 201-1000 / 1000+) · 주요 용도(광업 · 대형 건설 · 농업 · 임업 · 일반 건설 · 렌탈 · 기타) · 장비 보유(0 / 1-3 / 4-10 / 11+) · 의사결정 역할(소유자 · 구매 · 영향 · 운영자).
2/4 — 사용 환경현장 환경 · 연 가동시간 등 보조 축.
3/4 — HD 경험HD 인지도 · 만족도 · 관심 모델(선택).
4/4 — 추천NPS 0–10 + 결과 카드(세그먼트 · 추천 모델 3종 · 카탈로그 QR · 연락처 옵트인).

특징

  • 오프라인 작성 가능 — 부스에서 인터넷이 잠시 끊겨도 응답 작성에 영향이 없습니다.
  • 홈 화면 추가 지원 — 방문객이 원하면 자신의 휴대전화에 "앱처럼" 설치할 수 있습니다(거의 사용되지는 않음).
  • 익명 응답 — 개인 식별 정보를 받지 않고, 같은 휴대전화로 중복 응답이 막힙니다.
2분 룰. 18문항을 95% 이상의 응답자가 120초 이내에 끝낼 수 있도록 문항 수·문구·인터랙션을 조율했습니다. 부스 통행을 막지 않기 위함이며, 18문항 중 6개는 명시적으로 "선택"으로 표기됩니다.
STEP 3 · CRM 자동 캡쳐

Sensor 채널 — CRM 화면 자동 캡쳐와 본사 검토

사람이 설문을 하는 동안 백그라운드에서 진행되는 자동 흐름. 부스 PC에 설치된 Chrome 확장 프로그램이 딜러의 CRM(Bitrix24) 화면을 자동으로 캡쳐해 본사로 보냅니다. 본사 서버는 캡쳐 5장을 한 거래(deal)로 묶고, AI 비전 모델로 13개 영업 필드를 자동 채워 줍니다.

3-1. 부스 PC의 확장 프로그램

딜러 식별자, 송출 대기 큐 / 실패 / 24시간 완료 카운트, 그리고 큐 강제 송출 · 로그 보기 · 큐 비우기 액션이 있습니다. 평상시 운영자가 신경 쓸 일은 없고, 송출 대기 큐가 비정상적으로 쌓일 때만 본사가 원격으로 확인합니다.

3-2. 본사 Sensor 콘솔 — 캡쳐 목록 · 클러스터 · 13 필드

캡쳐 목록 상단 필터전체 / 미검토 / 저신뢰(70% 미만) / 편집됨 / 실패·재시도. 최근 24시간 캡쳐 67건.
캡쳐 행캡쳐 시각 · 딜러 ID · CRM 종류 · 화면 종류(거래 상세 / 회사 / 담당자 / 활동 / 깔때기) · 거래 ID · 상태 · 분류 신뢰도.
클러스터 상세같은 거래로 묶인 캡쳐 5장 · 정규화 상태 · 사용된 AI 모델과 프롬프트 버전 · 재정규화 버튼.
정규화 결과 — 13 필드거래 ID · 회사명 · 담당자 · 연락처 · 예산 · 단계 · 관심 장비 · 지역 · 담당 딜러. 각 필드별 신뢰도 표시 + 수동 편집 버튼.
편집 이력날짜 · 필드 · AI가 추출한 원본 → 사람이 수정한 값 · 편집자 · 사유. 모든 수정이 감사 로그로 남습니다.

3-3. EntityCluster — 캡쳐 5장이 한 거래로 묶이는 그림

승인 흐름. 자동 정규화 결과는 기본 "검토 필요" 상태로 들어옵니다. 마케팅팀이 목록에서 클러스터를 선택 → 13 필드를 확인하고 필요하면 편집 → 행 단위로 승인하거나 재정규화를 요청합니다. 사람이 수정한 내용은 다음 캡쳐 정규화 정확도를 끌어올리는 입력으로 다시 사용됩니다.
STEP 4 · Voice 검토

Voice 응답 콘솔 — 응답 검토와 인사이트

한국 본사가 Voice 채널 응답을 한 화면에서 확인. 딜러 인터뷰와 방문객 설문 응답을 통합 시각화하고, 8개 세그먼트 분포·NPS·언어 분포 같은 인사이트를 즉시 산출합니다.

응답 목록 필터유형(전체 / 딜러 / 방문객) · 세그먼트(광업 · 키 어카운트 · 대형 건설 · 렌탈 · 농업 · 임업 · 일반 건설 · 기타) · NPS 범위 · 옵트인 여부 · CSV 내보내기.
응답 행시각 · 유형 · 세그먼트 칩 · NPS 점수(색상 코딩) · 언어 · 수신 확인 · 옵트인 · 발신자.
인사이트 메트릭총 응답 67 · NPS 평균 8.2 · Promoter 22(42%) · Detractor 8(15%) · 기간·이벤트 필터.
세그먼트 분포8개 세그먼트 가로 막대 그래프. 광업 12 · 대형 건설 11 · 키 어카운트 9 · 농업 7 · 렌탈 6 · 임업 5 · 일반 건설 4 · 기타 8.
이벤트·언어 분포이벤트별 응답 수 · 응답 언어 분포(러시아어 48 · 영어 15 · 한국어 4).
의도된 단순화. Voice 콘솔이 답해야 할 질문은 "오늘 어느 리드가 가장 뜨거운가" 한 가지입니다. NPS 9 이상 + Promoter로 필터 → 상단으로 정렬 → CSV로 영업팀에 전달. 나머지 데이터는 화면 개선과 정확도 보정의 원료입니다.
STEP 5 · 통합 깔때기

통합 리드 — Sensor + Voice가 같은 회사로 묶이는 자리

자동 캡쳐(Sensor)와 설문 응답(Voice) 두 채널이 같은 회사를 다른 시점·다른 형태로 잡았을 때, 통합 리드 화면에서 한 건으로 응집됩니다. 통합된 리드에는 자동 산출된 점수·우선순위·영업 멘트가 함께 표시됩니다.

리드 목록우선순위(P1/P2/P3) · 점수(0-100) · 세그먼트 · 회사명 · 채널 표식(자동 캡쳐 N건 + 설문 N건) · 금액 · 단계 · 최근 활동. 채널 필터(전체 / Sensor만 / Voice만 / Sensor+Voice).
리드 상세 카드점수 92 · 우선순위 P1 · 세그먼트 key_account · 채널 표식(자동 캡쳐 3 + 설문 2).
예산·요약회사명 · 담당자 · 연락처 · 금액 · 단계 · 관심 장비 — Sensor에서 자동 추출된 13개 필드.
영업 멘트 (Playbook)점수와 세그먼트에 맞춰 자동 발급되는 영업 가이드. 한 페이지에 들어가는 분량으로 영업 담당이 바로 사용 가능.
Sensor 원본13 필드의 원본값과 신뢰도, 어느 캡쳐 클러스터에서 왔는지 추적.
Voice 원본딜러 인터뷰 1건 + 방문객 응답 1건 — 시각·NPS·세그먼트·옵트인.
연결 이력같은 회사로 묶인 모든 채널 데이터의 시간순 목록. 잘못 묶였을 경우 수동 해제도 가능.
한 화면 원칙. 영업 담당이 리드 한 건에 대해 알아야 할 모든 정보가 이 한 페이지에 들어갑니다. 두 채널 데이터를 따로 떠다닐 일이 없도록 같은 회사로 자동 응집되며, 자동 응집이 잘못된 경우는 사람이 한 번에 분리/병합할 수 있습니다.
STEP 6 · 캠페인 설문

설문 빌더 — 새 이벤트용 설문을 자연어로 만들기

새 캠페인·새 이벤트가 잡히면 마케팅팀이 자연어로 한두 문단 브리프를 적습니다(예: "러시아 광업 대형 사업자 대상, 가동시간·디젤 가격·환경 규제 위주, 31문항"). 빌더가 그 브리프에서 31문항짜리 설문 초안을 자동 생성해 검토·편집 후 부스 화면에 배포합니다.

① 자연어 입력대상(딜러 31문항 / 방문객 18문항) · 이전 버전 자동 보관 옵션. 자유 텍스트로 캠페인 의도를 한두 문단 작성. 시드 예시 칩이 우측에 제공.
② 빌드 결과 요약예상 응답 시간 · 검토할 문항 수 · 사용된 프롬프트 버전 · 토큰 사용량. 빌드 직후 한눈에 품질을 가늠.
③ 생성된 설문 검토·편집31문항이 한 페이지에 펼쳐지고 각 문항 인라인 편집 가능. 응답 유형(단일 선택·다중 선택·1~5 점수·NPS·동의) · 필수 / 선택 · 핵심 축 라벨이 자동 부여.
④ 휴대전화 미리보기우측에 실제 디바이스 사이즈로 미리보기가 실시간 갱신. 배포 전에 한 문항씩 시뮬레이션 가능.
⑤ 배포설문 버전 번호가 자동 부여되고, 같은 대상의 이전 설문은 자동 보관 처리. 부스 화면에 즉시 반영(다운타임 없음).
